## Corrections to our own earlier reviews

1. **P5 (findings-2026-10-12) was wrong.** Under the pinned xgboost 3.4.1,
   Morgan fingerprints on `parent_smiles`, the repo random split, and a fit on
   train+valid give R² 0.6814376116 for egfr_full/random, equal to the
   committed value. We had used xgboost 3.2.0, where the same fit gives
   0.6895. Our reasoning that version effects were "ruled out" because a
   different train-only number matched under both versions does not hold:
   version sensitivity is cell-specific.
2. **P2's per-tag mechanism labels were partly wrong** (see R2 below): a2a is
   a level effect, not shrinkage, and herg is not compression.
3. Minor: the AFP hivpr/scaffold seed-1 R² is 0.508, not 0.509; and
   `findings-2026-10-11.md:92` credits the "258 `=` rows without pChEMBL"
   measurement to the 2026-10-10 review, while it came from the PR #2
   verification.

## Medium

### R1. Single-seed dependence is caveated for 1 of 14 cells

- **Where**: `README.md:299`, `:310-312`, `:482-488`, `:499-502`;
  `docs/methodology.md:388`, `:397-402`, `:836-857`; PR description item 2.
- **Evidence**: an independent paired bootstrap (B = 10,000, ensemble = mean
  of the kept seeds) over all 48 GIN, GINE and AttentiveFP random/scaffold
  cells reproduces every committed mean3 row, and finds 14 cells whose verdict
  changes when any one training seed is dropped:

  | Group | Cells that change | Caveated in README |
  |---|---|---|
  | GNN wins (5) | 4: GIN abl1/scaffold, GIN herg/random, AFP herg/random, AFP herg/scaffold | 0 |
  | RF wins (21) | 1: AFP hivpr/scaffold | 1 |
  | Ties (22) | 9 become RF-significant | 0 |

  Examples: GIN abl1/scaffold +0.038 [+0.006, +0.069], drop seed 42 +0.015
  [−0.017, +0.046]; AFP herg/random +0.034 [+0.002, +0.065], drop seed 42
  +0.003 [−0.031, +0.035]. Only GINE abl1/scaffold survives every drop (worst
  +0.047 [+0.017, +0.080]). README still calls GIN herg/random "small but
  real" and GIN abl1/scaffold "a real flip"; methodology calls abl1/scaffold
  "the one real GIN lead". The PR description says 8 of 32 AFP/GINE cells
  were given conditional wording; one was.
- **Effect**: it strengthens the headline. RF's advantage is robust (1 of 21
  RF wins is seed-dependent); the GNN wins mostly are not.
- **Fix**: one standard for every model, for example: "Verdicts come from the
  paired-bootstrap CI of the 3-seed ensemble. A verdict that changes when any
  one training seed is dropped is marked conditional: 14 of 48 cells, namely
  4 of the 5 GNN wins (all but GINE abl1/scaffold), 1 of 21 RF wins, and 9
  ties that become RF-significant."

### R2. Time split: report the error decomposition instead of mechanism labels

- **Where**: `README.md:759-776`; `docs/methodology.md:538-569`;
  `experiments/LOG.md:878-880`.
- **Evidence**: from the committed time-split predictions, GIN-minus-RF R²
  splits exactly (residual 0) into a level term, a spread term and a
  correlation term (Shapley split of the MSE decomposition):

  | Tag | GIN − RF R² | Level | Spread | Correlation |
  |---|---|---|---|---|
  | a2a | +0.326 | +0.580 | +0.008 | −0.263 |
  | abl1 | −0.236 | −0.002 | −0.115 | −0.119 |
  | egfr | +0.039 | +0.005 | +0.079 | −0.045 |
  | egfr_full | +0.592 | +0.392 | +0.032 | +0.168 |
  | herg | +0.032 | +0.005 | −0.016 | +0.044 |
  | hivpr | +0.115 | −0.000 | −0.008 | +0.123 |
  | mpro | +0.084 | +0.025 | +0.027 | +0.032 |
  | vegfr2 | −0.052 | +0.035 | +0.002 | −0.089 |

  On a2a the RF predicts 0.83 log units too low (mean 6.51 versus test 7.35)
  while ranking better (r 0.59 versus 0.30); an RF re-centred on the non-test
  mean scores +0.335, above the GIN's +0.024. On herg the GIN has more spread
  than RF (0.44 versus 0.41), so "compression" does not describe it. Only egfr
  fits "less over-dispersion", and only hivpr is clearly better correlation.
- **Fix**: replace the labels with this table, or use one clause per tag that
  matches it. Our own P2 wording should not be reused.

### R3. The trust-anchor refusal checks the name only

- **Where**: `scripts/fetch_artifacts.py:235`, `:286-293`, `:222-246`;
  the release body ("the trust anchor can never be overwritten").
- **Evidence**: a scratch copy of the script run with injected download
  functions against a scratch repo:
  - An archive with `payload/egfr_activities.csv`, a forged
    `payload/sha256sums.txt` and a symlink `data/raw -> ../payload` prints
    "repo checksums ok … verified and installed", exits 0, and the tracked
    manifest now holds the forged pins. The `data` tar filter allows in-tree
    links and `move_tree` follows directory symlinks, so this works on any
    filesystem.
  - A member named `data/raw/SHA256SUMS.txt` does the same on macOS.
  - After either, a second run with a stale local CSV passes.
  - Any non-manifest member is installed unverified anywhere in the repo:
    `results/metrics_egfr.json` (which gnn_01 verifies against),
    `scripts/02_clean_data.py`, `.git/hooks/pre-commit`. This predates the PR
    (Low, latent).
- **Fix**: accept only regular-file members under a per-asset prefix
  allowlist; refuse symlinks and hardlinks; compare the anchor path
  case-insensitively; after the move, check the anchor on disk is a regular
  file whose bytes equal the copy read at start. Add tests for each case;
  6 of 7 mutants of the new behaviour currently survive
  `tests/test_fetch_artifacts.py`.

### R4. Users with existing local raw files are locked out

- **Where**: `scripts/fetch_artifacts.py:330-334`, `:275-282`, `:60-64`.
- **Evidence**: a scratch repo in the state an artifacts-v1 user has (old
  egfr CSV, no `document_years.csv`, old model): `--all` prints "already
  extracted, skipping" for models and raw, then aborts with "the release
  likely predates the 2026-10-11 data refresh", makes no download, and never
  reaches the processed cache. Clearing `.artifacts_cache/` as advised gives
  the same error. Deleting the stale CSV works, which is what the message
  tells users not to do. Separately, a single local
  `egfr_fingerprints.npz` or `rf_random_split_egfr.joblib` makes the whole
  cache or models asset count as installed.
- **Fix**: on a failed skip-path check, fall through to download and verify,
  or name the files to delete; check every key file of an asset, not one.

### R5. The headline EGFR GIN runs have no committed log, and the device statement is false for them

- **Where**: `docs/methodology.md:287-297`; `results/gnn_metrics_egfr{,_seed1,_seed2}.json`.
- **Evidence**: the committed egfr GIN test R² (random 0.6694 / 0.6608 /
  0.6636, scaffold 0.6308 / 0.6074 / 0.5991, time 0.0404 / 0.0325 / 0.1913)
  appear in no committed log (`grep -rl "R2=0.6694" logs` is empty). The egfr
  blocks in `logs/win4070_/win4070_gin_c.log` report different values
  (random 0.7055 / 0.6989 / 0.7124, scaffold 0.4931 / 0.5102 / 0.5092) and
  appear to predate the egfr re-pull. These are the numbers behind the
  README's GNN-versus-RF headline table. Methodology says every committed GIN
  panel run trained on the CUDA host.
- **Related (Low)**: the 2026-10-11 learning-curve and y-randomization GIN
  trainings ran on the Mac and are not mentioned; `experiments/LOG.md:5` still
  says results were produced on the M3 Max.
- **Fix**: commit the egfr GIN training logs (or rerun and log them), and
  scope the device sentence to the runs the logs cover.
