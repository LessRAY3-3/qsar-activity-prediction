## Correction to our own N4

`findings-2026-10-11.md` N4 said the GIN's time-split advantage "is largely
GIN shrinking to the mean". That is only true for a2a and herg. On egfr_full
the GIN's prediction spread is close to RF's; its gain comes from the
prediction level moving toward the newer test mean:

| egfr_full / time | Mean pIC50 | Pred std / y std |
|---|---|---|
| Non-test pool | 6.69 | |
| Test set | 7.50 | |
| RF predictions | 6.62 | 0.57 |
| GIN ensemble predictions | 7.04 | 0.52 |

A plausible cause is that GIN checkpoints are selected on the newest pre-test
years, which RF never sees. hivpr and mpro are also not explained by
shrinkage. The PR adopted our wording, so P2 below asks to correct it.

## Medium

### P1. N3: the 60-epoch floor never bound; the flip is a fresh draw on another device

- **Where**: `README.md:469-471`; `docs/methodology.md:746-748`, `:283`;
  `experiments/LOG.md:837-845`; `scripts/gnn_03_train_gin.py:207-224`, `:298-316`.
- **Claim**: the docs say abl1/scaffold AFP stopped being RF-significant
  because the stalled seed-42 run "was rerun with a 60-epoch early-stop
  floor". In the committed rerun log the floor never mattered, and the run
  was on a different device.
- **Evidence**: improvement epochs in
  `logs/review11_n3_afp_abl1_scaffold_s42_min60.log` are 1-11, 15, 24, 26, 27,
  29, 31, 33, 35, 41, 45, 46, 62, 69-71, 82. The largest gap is 18, below
  patience 20, so simulating the stop rule with `min_epochs` 0 or 60 gives the
  same 100-epoch run. The rerun log says `device=mps`; the original says
  `device=cuda`, and the two diverge from epoch 2 (valid 0.9411 versus
  0.9546). Of 159 runs matched to logs, 158 ran on CUDA, while
  methodology.md:283 says GNNs were trained on an Apple M4 (MPS). The metrics
  json has no device field.
- **Related**: AFP hivpr/scaffold "RF significant" also hinges on one seed
  (R² 0.201 versus 0.509 and 0.377). All three seeds give −0.062
  [−0.123, −0.003]; without seed 42 it is −0.013 [−0.076, +0.046], a tie. A
  drop-one-seed sweep finds 8 of 32 AFP/GINE cells whose verdict depends on a
  single seed; none is caveated. The convergence rule (best epoch below 30% of
  the maximum and train MSE above 0.5) was calibrated on this one run and
  flags no other committed run, except possibly one borderline GIN time run.
- **Fix**: say the cell changed on an independent rerun on MPS, not because
  of the floor; record the device in metrics json; correct methodology.md:283.
  Either report single-seed-dependent cells as conditional, or rerun every
  flagged or outlying seed under one rule on one device.

### P2. Time split: "the GIN edge is largely shrinkage" is wrong for three of four GIN wins

- **Where**: `README.md:698-702`; `docs/methodology.md:489-498`, `:472`.
- **Evidence** (recomputed from the committed time-split predictions; the
  constant baseline matches the stored `constant_r2` to 8e-9):

  | Tag | Constant R² | RF R² | GIN ens R² | Pred std / y std RF vs GIN | Slope on truth RF vs GIN |
  |---|---|---|---|---|---|
  | a2a | −0.004 | −0.301 | +0.024 | 0.69 vs 0.22 | 0.41 vs 0.07 |
  | egfr_full | −0.455 | −0.736 | −0.144 | 0.57 vs 0.52 | 0.06 vs 0.14 |
  | hivpr | −0.006 | −0.027 | +0.088 | 0.53 vs 0.54 | 0.14 vs 0.20 |
  | mpro | −0.000 | +0.006 | +0.090 | 0.46 vs 0.32 | 0.12 vs 0.10 |

  Shrinkage explains a2a and herg. On hivpr the GIN has more spread and a
  higher slope than RF; on egfr_full the gain is the prediction level (see
  the correction above).
- **Also**: "stays closer to the no-skill baseline" is equated with Δ > 0 on
  6 tags, a different quantity (`README.md:614`, `:689-691`); and the RF is
  compared with a constant built partly from validation years the time RF
  never trained on, disclosed only in methodology (`README.md:693-697`).
- **Fix**: scope the reading per tag: shrinkage for a2a and herg, level shift
  for egfr_full, genuine extra signal for hivpr and mpro. Drop "largely".

### P3. fetch_artifacts verifies the archive against a manifest the archive just overwrote

- **Where**: `scripts/fetch_artifacts.py:258` (extract), `:197-203` (read the
  manifest), `:265-268`; README "fetched assets are verified twice".
- **Claim**: `run()` extracts `raw_data.tar.gz` into the repo root first, then
  `verify_extracted_raw()` reads `data/raw/sha256sums.txt`. The artifacts-v2
  release body says the archive contains `data/raw/sha256sums.txt`, so
  extraction replaces the tracked trust anchor before it is read.
- **Evidence**: an unmodified copy of `fetch_artifacts.py` with injected
  download functions, run against a scratch repo whose pinned manifest is
  correct: an archive with a stale CSV and no manifest member fails as
  intended; the same stale CSV plus a matching `data/raw/sha256sums.txt` in
  the archive prints "repo checksums ok", exits 0, and leaves the tracked pin
  overwritten. Member order does not matter.
- **Related (Low)**: archive members not in the manifest, such as
  `document_years.csv` which drives every time split, are extracted
  unverified; models have no repo-side manifest, and an existing
  `models/rf_random_split_egfr.joblib` or a cached v1 archive is reused
  without any check; the failure message tells the user to delete
  `data/raw/`, which removes the tracked manifest; `tests/test_fetch_artifacts.py`
  never uses an archive that ships its own manifest.
- **Fix**: read the repo manifest before extracting, or extract into a temp
  dir and verify there; refuse archive members that would overwrite
  `data/raw/sha256sums.txt`; add the missing test case. Optionally add a
  models manifest and key the cache by release tag.

### P6. GNN-variant framing: two claims the committed runs do not support

- **Fairness "lower bound"** (`README.md:390-392`, `:418-427`, added in
  37ade91). The README says the tuning gains "are lower bounds" and a wider
  grid "could only have found more". Both rest on abl1/scaffold tuned GIN
  +0.056. The same config (256 / 5 layers / 0.2) with the same seeds was run
  twice by `gnn_fairness.py`:

  | abl1 / scaffold, 256/5L/0.2 | Test R² (3-seed mean) | Δ vs RF 0.714 |
  |---|---|---|
  | Tuning phase | 0.734 | +0.019 |
  | Final phase | 0.770 | +0.056 |
  | Frozen GIN | | +0.022 |

  The run-to-run gap (0.036) exceeds the claimed lift. Validation rank also
  does not track test rank: 3 of the 7 non-winning configs score better on
  test than the winner. A larger grid can select a worse model.
- **"Bond features move exactly one cell"** (`README.md:336-341`, added in
  37ade91). Against the frozen GIN, GINE changes 5 of 16 mean3 verdicts
  (a2a/random, a2a/scaffold, herg/random, hivpr/random, hivpr/scaffold), adds
  no new win, and loses the GIN's herg/random win. The same paragraph calls the
  GINE win "within multiple-comparison noise", while README:292, :303-305 and
  methodology:370-371 call weaker GIN wins on the same panel "real".
- **Related (Low)**: README sets the fairness-campaign GINE numbers next to
  the panel GINE numbers for the same cells without saying they are separate
  trainings; same-seed differences reach 0.066 R².
- **Fix**: remove "lower bound" and "could only have found more", and report
  the abl1 tuned result with its own replicate. Replace "exactly one cell" with
  the 5-of-16 comparison, and apply one significance standard to every model.
