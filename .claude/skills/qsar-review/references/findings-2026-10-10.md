## High

### H1. Censored IC50 records are trained and scored as exact values

- **Where**: `scripts/01e_download_chembl.py:36-40` and
  `scripts/01d_download_incremental.py:26-30` (`COLUMNS` has no
  `standard_relation`); `scripts/02_clean_data.py:28-43` (no relation
  filter); `scripts/02_clean_data.py:45-48` (sanity check).
- **Claim**: ChEMBL records such as "IC50 > 10000 nM" or "IC50 < 50 nM"
  enter the pipeline as exact 10000 nM / 50 nM, so a large share of the
  regression labels are detection limits, not measurements.
- **Why the existing check misses it**: ChEMBL leaves `pchembl_value`
  empty for every censored record. `chk = df.dropna(subset=["pchembl_value"])`
  therefore drops exactly the censored rows, and the README's "100%
  agreement with pchembl_value" is computed on uncensored rows only.
- **Evidence** (live ChEMBL, IC50 in nM, assay types B+F as downloaded;
  `scripts/chembl_censoring_counts.py --overlap TAG`):

  | Tag | Censored share of raw records | Compounds with ≥1 censored record | Compounds whose label is ONLY censored | Most common censored-only labels |
  |---|---|---|---|---|
  | `egfr_full` | 21.5% (5,283 / 24,560) | 27.6% | **20.1%** (2,718 / 13,497) | pIC50 5.0, 7.3, 6.0, 7.0, 4.0 |
  | `a2a` | 19.0% | 22.6% | **21.7%** (379 / 1,746) | pIC50 6.3, 5.0, 8.0 |
  | `abl1` | 18.3% | 24.8% | **20.5%** (554 / 2,698) | pIC50 5.0, 8.0, 6.0 |
  | `herg` | 28.5% | 31.0% | **29.7%** (3,572 / 12,019) | pIC50 5.0, 4.52, 4.0 |
  | `mpro` | 19.5% | 23.7% | **22.6%** (998 / 4,424) | pIC50 4.0, 7.0, 5.0 |
  | `vegfr2` | 20.7% | 24.4% | **17.8%** (2,096 / 11,797) | pIC50 5.0, 7.3, 6.0 |
  | `hivpr` | 7.6% | 8.6% | **7.8%** (217 / 2,799) | pIC50 9.0, 4.0, 5.0 |

  The EGFR raw total today (24,560) equals the committed `egfr_full` pull,
  so its numbers apply directly. Censored records never carry a pChEMBL
  value (0 of 5,283 for EGFR).
- **Failure scenario**: a compound reported only as "> 10 µM" is labelled
  pIC50 5.0. A model that correctly predicts 4.2 for it is penalised by
  0.8 log units; one that predicts 5.0 is rewarded. "< 50 nM" labels
  (pIC50 7.3) cap the potent end the same way. This also explains part of
  the "vertical striations at low pIC50" noted in `docs/methodology.md`
  (Data QC) and the "molecule-intrinsic" shared worst errors.
- **Effect on conclusions**: unknown until rerun. Both RF and GIN see the
  same labels, so the RF-vs-GIN verdicts may survive, but absolute R²/RMSE
  and the uncertainty/AD calibration numbers are computed against
  partly-censored targets.
- **Smallest fix**: add `standard_relation` (and `data_validity_comment`)
  to `COLUMNS`, then in `02` keep `standard_relation == "="`, or
  equivalently `pchembl_value.notna()`, and log how many rows and
  compounds that removes. A cheaper first step is a sensitivity run: drop
  the censored-only compounds from `egfr_full` and re-run RF on the random
  and scaffold splits.

## Medium

### M1. Salt forms are not stripped before deduplication

- **Where**: `scripts/02_clean_data.py:50-62` groups by raw
  `canonical_smiles`; `scripts/03_featurize.py:39-44` fingerprints the
  full multi-fragment SMILES.
- **Claim**: a hydrochloride and its free base become two "unique
  compounds" with separate labels, their fingerprints/graphs include the
  counter-ion, and the same parent can sit in train and test.
- **Evidence** (`scripts/qc_salts_censoring.py`; split leakage recomputed
  with the repo's own `train_test_split(random_state=42)` and
  `scaffold_split`, matching the tracked `egfr_*.npz` exactly):

  | Tag | Multi-fragment SMILES | Parents under >1 SMILES | Max pIC50 spread in a parent | Test molecules whose parent is in train (random / scaffold) |
  |---|---|---|---|---|
  | `egfr` | 204 (3.3%) | 43 | 3.06 | 15 / 0 |
  | `egfr_full` | 244 (1.8%) | 57 | 2.73 | 13 / 6 |
  | `herg` | 390 (3.2%) | 30 | 2.09 | 16 / 17 |
  | `vegfr2` | 270 (2.3%) | 64 | 1.48 | 21 / 0 |
  | `abl1` | 68 (2.5%) | 27 | 0.84 | 11 / 0 |
  | `mpro` | 135 (3.1%) | 8 | 0.40 | 6 / 0 |
  | `hivpr` | 17 (0.6%) | 6 | 2.43 | 4 / 0 |
  | `a2a` | 13 (0.7%) | 1 | 0.82 | 0 / 0 |
  | `bace` | 0 | 0 | - | 0 / 0 |

  Leakage is small (at most ~1.7% of a test set) and will not move the
  headline numbers, but scaffold leakage is not zero for `herg` and
  `egfr_full` because ring-bearing counter-ions change the Murcko string.
- **Smallest fix**: in `02`, map each SMILES to its parent with
  `rdMolStandardize.LargestFragmentChooser` (optionally `Uncharger`)
  before grouping. This changes row counts, so it belongs with a data
  refresh such as H1.

### M2. Scaffold-split RF refits reuse the random split's grid winner

- **Where**: `experiments/fingerprint_ablation.py:114`,
  `experiments/learning_curve.py:76`, `experiments/y_randomization.py:159`,
  `experiments/interpretability_alignment.py:277`.
- **Claim**: all four read `best_params_random` and apply it to the
  scaffold split too, although `metrics_{tag}.json` now carries a
  separate `best_params_scaffold` (backfilled in 0b9f48d).
- **Evidence**: the two winners differ for 7 of 9 tags (a2a, abl1, egfr,
  herg, hivpr, mpro, vegfr2). For `mpro` all three grid keys differ
  (300/None/5 vs 500/40/2).
- **Failure scenario**: the fingerprint-ablation docstring says the
  r=2/2048 anchor "IS the headline" model; on scaffold it is a different
  forest that happens to pass the 0.01 tolerance (0.5582 vs 0.5624 for
  egfr). `interpretability_alignment` explains a forest whose errors did
  not select the molecules it explains (see L4).
- **Smallest fix**: `bp = mj[f"best_params_{split}"]` inside the split
  loop, falling back to `best_params_random` with a printed note.

### M3. XGBoost "3 seeds" are three identical models

- **Where**: `experiments/xgboost_baseline.py:141-145`.
- **Claim**: `XGBRegressor(random_state=seed, tree_method="hist")` with
  default `subsample=1.0` and `colsample_*=1.0` has no randomness, so the
  seed changes nothing.
- **Evidence**: `results/xgboost/xgboost_egfr.csv` has three byte-identical
  rows per split (R² 0.73155… ×3, 0.51725… ×3); `summary_egfr.json`
  reports `r2_std: 0.0`.
- **Fix**: set `subsample=0.8, colsample_bytree=0.8` (and re-run), or
  state that XGBoost is deterministic and drop the error bars.

### M4. Time-split Δ column is mislabelled, and the README table invites a wrong subtraction

- **Where**: `experiments/time_split_summary.py:41` and `:132`;
  `README.md:398-407`.
- **Claim**: `d_r2_mean3` is the ensemble-point Δ (R² of the 3-seed mean
  prediction minus RF R²) for both point and CI, but `DELTA_CONVENTION`
  says `point=per-seed-mean_R2`. The README time table puts per-seed-mean
  GIN R² next to the ensemble Δ.
- **Evidence**: `herg` row reads RF −0.034, GIN −0.076, Δ **+0.076**. The
  two displayed columns give −0.042 (GIN worse); the Δ and its CI say
  GIN significantly better. For `a2a` the columns give +0.158 while Δ is
  +0.238. `tests/test_time_split_summary.py:36-37` compares the constant
  with itself, so it cannot catch this.
- **Fix**: set the constant to `point=ensemble_mean-pred_R2;ci=ensemble_mean-pred_R2`
  for this table, and either add an ensemble GIN column to the README
  table or add one sentence under it saying the Δ is not the difference
  of the two displayed columns.

### M5. README misattributes the y-randomization control gap

- **Where**: `README.md:163-170`, `docs/methodology.md` (y-randomization
  write-up); code at `experiments/y_randomization.py:182`.
- **Claim**: the README says the 0.7414 vs 0.7466 gap comes from fitting
  one RF with the grid winner instead of re-running GridSearchCV. The
  code fits the control on `train_idx` only, i.e. without the 10%
  `valid_idx` carve-out that the headline RF trained on.
- **Evidence**: the fingerprint-ablation seed-42 row refits the same
  params on train+valid and gets 0.7459; the learning-curve RF at
  n≈4,400 gets 0.7411, matching the control.
- **Fix**: one-sentence README/methodology change ("trained on the GNN
  train pool, i.e. without the validation carve-out"), or fit the control
  on `pool`.

## Low

### L1. `p_one_sided` is P(ΔR² > 0), not a p-value for a GIN win
`experiments/paired_bootstrap.py:235`. For a strong GIN win it reads ≈1.0
(e.g. `a2a`/time: Δ +0.238, CI [0.129, 0.347], `p_one_sided=1.0`). Anyone
filtering `p < 0.05` drops every GIN win. The formula is documented in
methodology; renaming the column (`frac_boot_gin_better`) or adding
`p_two_sided = 2*min(p, 1-p)` removes the trap.

### L2. A partial bootstrap run overwrites the campaign summary
`experiments/paired_bootstrap.py:420-431` rewrites `summary{suffix}.csv`
and the forest plot from the current invocation only. `--tags egfr` or a
`--n-boot 300` smoke test replaces the 32-row B=10,000 table the README
cites. `gine_panel.py`/`afp_panel.py` then fail on missing cells (loud,
not silent). Merge by `(tag, split, pair)` like `04`'s metrics merge.

### L3. Grid-search CV folds are not shuffled on scaffold/time splits
`scripts/04_train_and_evaluate.py:89-96` uses `cv=5`, i.e. unshuffled
`KFold`. Scaffold-split train indices are ordered by scaffold-group size
and time-split ones follow the SMILES-sorted clean CSV, so folds are
blocks of related chemotypes or alphabetical SMILES. No test leakage;
only the choice among 12 grid points is affected. Use
`KFold(5, shuffle=True, random_state=42)` or a `GroupKFold` on scaffolds,
and say which.

### L4. `interpretability_alignment.py` explains a different RF
`experiments/interpretability_alignment.py:276-284` retrains an RF with
`best_params_random` on the scaffold GNN train pool, while the molecules
were selected by `err_rf` from the committed
`models/rf_scaffold_split_{tag}.joblib` (train+valid). The SHAP
background is `train_idx[:200]`, which on the scaffold split is one or
two scaffold families because indices are grouped by family. Docstring
nits: it says "SMARTS" but the queries are parsed with `MolFromSmiles`
(lines 49-50), says "node-mask attribution" but uses
`node_mask_type=None, edge_mask_type="object"` (lines 136-141), and
`results/interpretability/findings.md:24` says no checkpoint existed for
the pool.

### L5. Latent robustness issues (current results unaffected)
- `scripts/gnn_04_compare.py:65-72,92`: `gin_n_seeds = len(files)`; a seed
  file missing one split gives a 2-run mean labelled as 3.
- `experiments/multi_target_summary.py:345`: `np.allclose` without
  `equal_nan=True` fails the round-trip when a tag lacks one split,
  contradicting "skipped tags still exit 0".
- `experiments/uncertainty_ad.py:213-216` vs `:561-568`: the partial-seed
  warning is printed, then `gnn_ensemble_predict` raises on the first
  missing checkpoint.
- `experiments/gine_panel.py:189`, `experiments/afp_panel.py:175`: bar
  colour uses the sign of the per-seed-mean Δ while significance comes
  from the ensemble CI; a cell with point −0.01 and CI [+0.01, +0.05]
  would be painted "RF significantly ahead".
- `experiments/multi_target_summary.py:247` and
  `experiments/time_split_summary.py:230-231` print hard-coded verdicts
  and numbers next to recomputed ones.

### L6. Environment and dependencies
- `requirements.txt` pins `numpy==2.5.3`, which needs Python ≥ 3.12; the
  README fast path (`pip install -r requirements.txt`) does not say so and
  fails on 3.11. CI and `environment.yml` use 3.12, so CI is fine.
- `requests` (`scripts/01d`, `01e`, `fetch_document_years.py`) and `scipy`
  (`experiments/scaling_analysis.py`, `07_qc_checks.py`) are imported
  directly but only arrive transitively.
- Std conventions are mixed: JSON summaries use `np.std` (ddof 0), figures
  use pandas `.std()` (ddof 1), e.g. `experiments/xgboost_baseline.py:56`
  vs `:160`.

### L7. README wording and rounding
- `README.md:240`: `mpro`/scaffold mean3 Δ is −0.0855, which rounds to
  −0.085, not −0.086 (same in methodology).
- `README.md:164`: "both models collapse to R² ≤ 0"; shuffled GIN seeds on
  egfr/random are −0.029, +0.002, +0.011. The group means are ≤ 0.
- `README.md:392`: test fractions above 20% are listed only for `a2a`
  (62%) and `mpro` (51%); `egfr_full` 25.5%, `abl1` 25.0% and `hivpr`
  23.6% also overshoot.
